# 真实账号 stdio MCP 只读联调

执行日期：2026 年 10 月 23 日。用户将正常登录后的网络学堂 Cookie 手动写入本地配置。服务自行读取该会话主页中的 CSRF，不输入密码、不重新登录、不绕过验证。

测试链路为官方 `Client` → `StdioClientTransport` → 编译后的 `dist/index.js` → 网络学堂 HTTPS 后端。仅允许调用 `get_course_list`、`get_homework_list`、`get_homework_detail`，脚本没有调用提交工具的分支。

## 通过的检查

| 工具 / 检查 | 结果 |
| --- | --- |
| 初始化和工具发现 | 成功发现四个工具及其 Schema |
| `get_course_list` | 成功返回本学期 11 门课程 |
| `get_homework_list` | 抽查课程返回 5 项，与浏览器核对结果相符 |
| 状态合并 | 未交 1 项、已交未批 1 项、已批改 3 项 |
| 未交详情 | 1 个题目附件；读取备注上限 500 字符、附件页面上限 1 GiB |
| 已交未批详情 | 2 个附件，其中已交附件 1 个；截止后的已交内容可读取 |
| 已批改详情 | 2 个附件，其中已交附件 1 个；已有结果可读取 |
| 截止时间 | 三个状态抽查详情与各自列表的标准化截止时间一致 |
| 输出结构 | 通过客户端与 Zod 的结构验证，保留 `null` 表达未知表单限制 |

每个状态抽取一项详情，并非遍历整个学期的全部作业。附件只解析元数据，没有下载、上传、改动或覆盖文件。`submit_homework` 的真实写入及提交后核验尚未执行，需要用户指定可提交的作业及本地文件。

## 根据真实响应修正的问题

已过期作业的详情页正常，但提交页面可能返回没有表单的 HTTP 200。原来获取详情时还会请求该提交页面，从而误报 `PROTOCOL_CHANGED`。现仅在仍有正常或补交窗口时读取提交表单，已关闭窗口返回说明并保留已交详情。

提交服务也相应调整：先核验已有回执；对于新的请求，先校验提交时间，再获取有效表单。这样截止后仍能确认已有回执，新的过期请求则返回 `DEADLINE_PASSED`。已加入两项针对性回归测试，最终构建及 36 项本地测试全部通过。

本地 `config/local.json` 与 `.state` 均被 Git 忽略，并从项目交付压缩包中排除。后续会话过期时，需要用户重新提供有效网络学堂 Cookie。
