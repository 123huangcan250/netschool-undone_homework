# 验证记录与账号验收

首次验证：2026 年 10 月 23 日。会话维护回归更新：2026 年 10 月 26 日。执行环境为 Windows PowerShell、Node.js 22.18.0、npm 11.17.0。

## 已执行验证

`npm run check` 完成 TypeScript 严格模式构建及 47 项 Node.js 测试，全部通过，其中包含 10 个只读评估问题的答案核对。另有 10 项 Python/Tk 桌面测试通过。本地测试数据全部为合成数据或根据实测结构重建的匿名表单，文件在测试临时目录中生成，结束后清理。这些本地测试不使用真实校园 Cookie。

桌面程序真实只读联调覆盖当前学期 11 门课程、10 项未交作业及其详情，正文和附件元数据均成功读取。删除按钮与详情区域已在实际最大化窗口内检查边界；布局测试覆盖三种窗口尺寸、三种字体缩放，并测试本地隐藏持久化、恢复和 Delete 快捷键。历史 MCP 抽查记录保留其当时的验证数量，不代表后续桌面程序只验证了一门课程。

另行执行 `npm run test:live`，通过真实 stdio 子进程及官方 MCP Client 调用三个读取工具，成功读取 11 门课程、抽查课程全部 5 项作业及三状态各一项详情。只读真实联调与本地测试分开记录，未调用提交工具。详见 [LIVE_MCP_TEST.md](LIVE_MCP_TEST.md) 和 [脱敏结果](evidence/live-mcp.json)。

## 尚未验证的项目

- 当前账号统一身份认证后的完整浏览器跳转、实际 Cookie 的 Domain / Path / SameSite 等属性。
- 全部作业类型的兼容性；MCP 已完成一门课程、三个状态的详情抽查，桌面列表已遍历当时本学期 11 门课程的全部未交作业。
- 当前部署的附加 CSRF / 一次性隐藏字段及分页字段是否支持。
- 其他课程或教师设置的格式、大小及小组作业限制；当前样本只确认单附件、压缩提示及页面公布的上限。
- 真实单附件提交、真实 ZIP 提交以及提交后的真实状态回读。
- 学校是否已有另一套原生多附件上传协议；目前只实现公开单附件协议加 ZIP。

这些项目需要本人有效会话，提交验收还需要本人明确指定可提交的作业与文件。当前任务只开发服务，没有代替用户选择真实作业并提交。

## 本人浏览器链路核对步骤

1. 在浏览器 Network 开启 Preserve log，访问网络学堂并按正常流程完成统一身份认证。
2. 记录目标域、状态码、Location 以及 Cookie 名称与属性；不要把 ticket 或 Cookie 值写进共享文档。
3. 进入本学期课程，打开作业列表，按 API 文档核对三个 POST 的 URL、`aoData` 和 JSON 路径。
4. 打开一项作业，确认 `xszyid` 与 `zyid`，核对描述 JSON、四类附件区域及已交内容区域。
5. 打开提交页面，核对 `fileupload`、隐藏字段、`accept` 和教师要求。存在不同协议时，先更新 `config/protocol.json`；字段语义变化时也需调整解析器。
6. 只读服务联调先运行 `npm run probe -- --config ...`，再指定 `--course` 查看列表与详情是否能解析。探测脚本不调用提交接口。
7. 使用本人明确选择、尚未截止且允许测试的作业与文件，在客户端调用 `submit_homework`。核对网页中的附件和正文、时间与提交状态，再将匿名化结果记录为账号实测。

不建议将原始 HAR 放入仓库。若需要定位接口变化，应在本地保留原件，只共享移除 Cookie、Set-Cookie、ticket、CSRF 值及个人信息后的样本。
